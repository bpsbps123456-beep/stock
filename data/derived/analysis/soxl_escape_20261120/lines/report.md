# SOXL 경고선·재매수선 공동 연구 (2026-11-20, Claude + Codex gpt-6.2-astra)

**결론: 느린 선은 통했다.** 정확한 바닥을 맞히는 대신 "경고선 아래면 대피, 재매수선 위로 올라타면 복귀"하는 두 줄 규칙은, 선이 느릴수록(2시간~일봉) 고르는 구간·급락 구간·2025년 모두에서 같은 평균 비중을 늘 들고 있는 것보다 나았다. 빠른 선(5~30분)은 호가 비용을 넣으면 무너졌다. 지표 `soxl_lines.pine`의 기본값은 **일봉 EMA10·20 두 줄 띠**이고, Codex가 반박 검증에서 유일하게 통과시킨 **5분봉 EMA200 ±2%**를 프리장 체결 전제의 대안으로 넣었다.

## 공동 연구 분담과 검증

| 단계 | 한 일 | 결과 |
|---|---|---|
| 엔진 검산(Codex) | `engine.py`를 쓰지 않고 원자료로 기준 규칙 2개 재계산 | 12개 값 전부 일치 |
| 탐색(Claude) | 이평선 724개 + 두 줄 띠 60개 | 느린 선 우위, 빠른 선은 비용에 무너짐 |
| 탐색(Codex) | 채널·N일 저가선·변동성 추적·앵커 VWAP 149개 | 30분 32봉 채널만 두 구간 비용 후 양수, 2025 실패 |
| Codex 후보 검증(Claude) | 채널을 단순 반복문으로 재계산 + 이웃 72개 | 숫자 일치·미래 정보 없음. 이웃의 10%만 세 구간 양수 → 취약 |
| Claude 후보 반박(Codex) | 후보 5개 독립 재계산 75개 값 + 이웃 58개·위약·비용·깨어 있는 시간·사건 제외 | 75개 전부 일치. 빠른 선(C2)만 keep, 일봉 띠 포함 나머지 fragile |
| 실행 조건 점검(Claude) | 빠른 선의 정규장 체결·깨어 있는 시간·프리장 비용 0.3%·이웃 33개 | 프리장 체결이 전제. 2026은 버팀, 2025는 0 근처~음수 |

- 두 사람의 판정이 갈린 곳: Codex는 사건이 많은 빠른 선을 통과시키고(위약 백분위 97/99, 가장 유리한 대피 3번을 되돌려도 고르는 구간 시점 값 +41.3%p), 일봉 띠는 취약으로 봤다(위약 85/94.5, 대피 10번 중 가장 큰 3번을 되돌리면 −38.3%p). Claude의 실행 점검에서는 빠른 선이 정규장 체결이면 무너지고 2025는 비용 후 음수였으며, 일봉 띠는 세 구간 모두 버텼다. 그래서 기본값은 일봉 띠, 빠른 선은 선택 사항으로 둔다.
- 시험 범위: Claude 724 + 60 + 실행 점검 40, Codex 149 + 검증 62, Claude의 채널 검증 72 — 합계 약 1,100개 설정. 대량 탐색의 선택편향이 있고, 위약 백분위는 이를 보정하지 않는다.

## 방법

- 자료: Alpaca SIP 1분봉 SOXL·SOXX 2025-01-02~2026-11-19(04:00~20:00 ET, 분할 반영). 2025년은 느린 선 예열과 보조 확인.
- 엔진 `code/engine.py`: 세션 시작 정렬 봉(트레이딩뷰와 같음), 신호는 완성된 봉으로만, 봉 완성 뒤 첫 1분봉 시가 체결(스탑은 직전 봉 선 값에 닿은 1분봉에서 min(시가, 선)), 손익은 보유 중인 1분봉의 시가→다음 시가 로그수익(밤사이 갭 포함).
- 구간: 고르는 구간 2026-01-02~10-14, 확인 구간 10-15~11-19(사용자가 본 급락), 2025는 장세 위험 확인용.
- 1순위 지표: 시점 값 = 규칙 로그수익 − 평균 비중 × 보유 로그수익(= 보유/대피 경로를 시간축으로 돌려 끼운 위약의 기대값). 급락장에서는 덜 들고만 있어도 보유를 이기므로 보유 대비 수익은 근거로 쓰지 않았다.
- 사후 변경(결과를 본 뒤 바꾼 것): ① 순위를 편도 비용 0.1% 차감 값으로 바꿨다(비용 0 순위 1위는 하루 33번 전환하는 5분봉 규칙). ② 급락 전에 이미 대피한 규칙은 확인 구간 시점 값이 0으로만 나와, 고르는 구간 평균 비중을 기준으로 한 값을 함께 봤다. ③ 두 줄 띠 계열 60개는 1차 결과 뒤에 선언하고 돌렸다. ④ 기본값을 일봉 띠로 둔 것은 검증 결과와 실행 조건을 함께 본 판단이다.
- 변수 시점: 선은 완성된 봉 값만 쓴다. 스탑 선은 직전 봉 값이다. SOXX 신호는 종가 판정만 썼다.

## 한계

- 급락 사례는 2026-10(확인 구간)과 2026-07·2025-04(고르는 구간·보조) 세 번뿐이다. 느린 선의 2026 대피는 11번이고 이득은 2번에 몰려 있다.
- 되돌림 장세에서는 헛대피가 이어진다(2026 대피 11번 중 6번). 대피 중 급반등(9/15~21 +26%)을 놓친다.
- 프리장 체결가는 1분봉 시가로 근사했다. 실제 호가 차이는 0.3%로 크게 잡아 봤지만 체결 수량은 보지 않았다.
- Pine은 이 환경에서 컴파일하지 못했다. pynescript 구문 검사와 파이썬 미러 대조(`code/pine_mirror.py`: 느린 선 종가 45번·닿으면 63번·빠른 선 391번 전환이 엔진과 정확히 같음)만 했다. 독립 의미 검토 에이전트는 사용량 한도로 중간에 멈춰 Claude가 직접 검토했다. 참고로 연장 240분 '닿으면' 설정은 재매수 1분봉 안에서 바로 선에 닿은 2025-05-27 한 번만 엔진(같은 1분 안 대피 불가)과 지표(대피)가 다르다.
- 트레이딩뷰가 1분 차트에서 일봉 이력을 얼마나 불러오는지에 따라 EMA20이 늦게 계산될 수 있다. 선이 안 나오면 오른쪽 위에 '기준 봉 이력 부족'이 뜬다. 일봉 확정 시각(16:00 직후 또는 다음 날 04:00 ET)도 사용자 화면에서 확인이 필요하다. 어느 쪽이든 검증한 실행 시각(다음 정규장 시가)보다 이르다.
- 지표 '규칙' 입력에서 느린 선(기본)·빠른 선·직접 설정을 고른다.
