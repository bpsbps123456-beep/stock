# 감정 범주 묶음 A 감사 (2026-10-17, 가격 연결 전)

> 범위: `emotion/` 아래 코드 5개(감사용 2개 포함)와 산출물 전부. 기준: `HYPOTHESES_addendum3.md`(동결)와 동결 문서 §2.  
> 가격·지수·수익 자료는 읽지도 계산하지도 않았다. 기존 모델·창 표·예측 파일은 고치지 않았다(지문 대조로 확인).  
> 재현: `py emotion/code/audit_batchA.py` → `emotion/audit_batchA.json`(모든 숫자).

## 결론

다섯 항목 모두 통과했다. 큰 문제는 하나다. 기존 사용자 검수지가 분류기 범주만 보여 줘서, 보고서가 답으로 낸 AI 라벨 비율을 확인할 수 없었다. AI 라벨 검수지를 따로 만들어 고쳤다.

| # | 항목 | 판정 | 근거 |
|---|---|---|---|
| ① | 가격·지수·수익 자료를 읽거나 만들었나 | 통과 | 코드가 읽는 파일은 `units.parquet`(열 지정), `windows_kr/us.parquet`, 라벨·조각·표본 대응표뿐이다. 그 셋을 포함한 parquet 9개(새 검수 대응표 포함)의 열 이름에 가격 열이 없다. 가져오는 모듈은 `blind_sample`·`lexicon_v02`(정규식만)와 sklearn뿐이다. 급락일 4일은 지시로 받은 목록이고 검수지 뽑기에만 쓴다(H02 규칙) |
| ② | 라벨러가 다른 조각·sample_key를 열었나 | 통과 | 라벨 파일에는 notes 칸이 없어 작업 기록(워크플로 하위 에이전트 13개)으로 확인했다. 각자 부록 3과 자기 조각(또는 겹침 파일) 하나만 열었다. 디렉터리 `ls`로 파일 이름만 봤다. 이중 라벨과 1차 라벨의 일치는 범주 91.0~93.5%, 확신도 76.0~80.5%, 5칸 모두 같음 60~64%다. 베꼈다면 100%에 가까웠을 것이다 |
| ③ | 키워드 규칙으로 기계 생성했나 | 통과 | 10회 이상 나온 낱말 가운데 한 감정 범주 순도가 0.9 이상인 낱말은 0개다(최고 '가즈아' 16회 중 HYPE 75%). 낱말 하나가 덮는 몫은 범주마다 20% 이하다. 낱말 규칙 나무(깊이 3·6·12)의 5겹 정확도는 0.630~0.635로, 모두 NEUT로 찍는 0.619와 비슷하다. 작업 기록상 라벨 표는 손으로 적었고, 스크립트는 형식을 옮기는 데만 썼다 |
| ④ | 떼어 둔 20%가 학습·C 선택에 섞였나 | 통과 | 나눔을 그대로 재현했다(학습 1,563·떼어 둠 391). 겹치는 단위·id는 0이다. CV 5겹은 모두 학습분 안이다. 저장된 벡터라이저 어휘 37,309개와 idf는 학습분만으로 맞춘 값과 같다(떼어 둔 쪽을 넣으면 46,733개). 저장 모형으로 다시 잰 정확도 0.6726은 보고값과 같다. 작업 기록상 `emotion_batchA.py`는 한 번만 실행했다(떼어 둔 결과를 보고 설정을 바꾼 적 없음) |
| ⑤ | 창 비율이 마감 전 단위만 쓰고 작성자당 1회인가 | 통과 | `window_emotion.parquet`을 독립 재계산했다. (창, 작성자, 범주) 쌍 수의 칸 차이 0, 감정판 비율·들뜸 지수의 최대 차이 0이다. 센 단위(국내 255,961·미국 262,502)는 모두 창 시작 이후·마감 전 시각이다. 중복 제거로 국내 173,979·미국 176,637단위가 빠졌다(한 창 한 범주에 한 작성자 최대 335단위). 장애 창(미국 9/24·9/25)은 비율이 모두 결측이다 |

## 문제 목록

| 심각도 | 문제 | 영향 | 조치 |
|---|---|---|---|
| 중 | 사용자 검수지 `review_200.json`은 묶음 A 밖 단위에 분류기 범주를 붙였다(NEUT 181/200). 부록 3 순서(3 라벨 → 4 검수 → 5 분류기)상 4단계 검수는 3단계 AI 라벨을 확인하는 자리다. 보고서의 '라벨로 본 비율'(조롱 13.7%·분노 9.8% 등)과 "타당성은 사용자 검수로 확인된다"는 문장이 이 검수지로는 확인되지 않는다 | 검수 일치율이 주로 'NEUT가 정말 중립인가'만 잰다. 감정 범주와 라벨 비율의 타당성은 검증되지 않은 채 남는다 | **고침**: `review_label_200.json`과 `review_label_key.parquet`을 만들었다. 묶음 A에서 급락일 340단위를 뺀 1,660단위 가운데 글 100·댓글 100을 단순 무작위로 뽑고 AI 라벨을 표시했다(HYPE 7·JOY 1·MOCK 22·DESP 12·ANGER 22·FEAR 8·NEUT 128). 보고서 §7에 안내 한 줄을 넣었다. 분류기 검수지는 그대로 둔다(배포 모형 확인용, 선택) |
| 하 | 창 요약 표(보고서 §6)에 96시간 초과 창 1개(K2026-09-28, 추석)가 들어 있다. 동결 §2.1은 판정에서 빼고 따로 보고하라고 한다 | 평균 차이는 감정판 최대 0.13%p(MOCK 49.77% → 49.64%), 들뜸 지수 −0.0840 → −0.0849로 작다. 창 표에는 `over96` 표지가 있다 | 기록만 했다. 판정 단계에서 `over96`인 창을 빼면 된다 |
| 하 | 창 비율에 '부모 글이 앞 창에 있는' 댓글이 들어간다(국내 6,470·미국 7,353). 모두 자기 창 마감 전에 쓴 댓글이라 누출은 아니다. 중간 검증 `feat_text`와 같은 규칙(자기 시각 기준 창)이다. 다만 라벨 표본 틀은 부모 창 마감 전(`pre_close_kr`) 댓글만 썼다 | 분류기를 적용한 모집단이 학습 모집단보다 조금 넓다(국내 댓글의 3.0%) | 기록만 했다 |
| 하 | 날짜를 확정하지 못하고 '가장 늦은 날'에 놓은 댓글(국내 17·미국 20)이 창 셈에 들어간다 | 동결 §2.2가 허용한다(마감 전 집계에서 빠지는 쪽으로만 틀린다) | 없음 |
| 하 | 떼어 둔 391단위 중 3단위가 학습분과 같은 글이다('고생하셨습니다', 'ppomppu', 'ㅋㅋㅋㅋ', 모두 NEUT) | 빼고 재면 정확도 0.670(보고 0.673) | 기록만 했다 |
| 하 | 전체 예측(`pred_units.parquet`)과 창 비율에 묶음 A 2,000단위(전체 271,595의 0.74%)가 들어 있고, 그중 학습 1,563단위는 학습분 위 예측이다 | 영향은 미미하다. `sampleA_split` 열로 뺄 수 있다 | 기록만 했다 |
| 참고 | 라벨 JSON에 notes 칸이 없다. 라벨러의 "다른 파일을 열지 않았다"는 진술은 워크플로 산출(StructuredOutput)에만 있다 | 이번에는 작업 기록으로 확인했다. 기록이 지워지면 다시 확인할 수 없다 | 이 문서에 확인 결과를 남긴다 |

| 파일 | 내용 |

| `emotion/review_label_key.parquet` (새) | 검수 id → 표본 id·unit_idx·날짜·조각·나눔·두 번째 라벨. SHA-256 `96d76bcfe7928c05268dc3336b7c618c73e4ee90dd09880eee3aacaa9b1f9658` |

## 사용자에게 남은 일

- `review_label_200.json`의 200건에 `user_ok`(맞음 true / 틀림 false)를 표시하고, 틀리면 `user_cat`에 맞는 코드를 적는다. 일치 75% 이상이어야 라벨 비율을 쓴다(부록 3 4단계).
- 분류기 검수지(`review_200.json`)는 배포 모형을 판정 칸에 쓸지 볼 때 추가로 쓸 수 있다. 다만 대부분 NEUT라 정보가 적다.
