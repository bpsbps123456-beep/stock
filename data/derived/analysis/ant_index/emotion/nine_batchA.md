## 점검과 한계

- 형식 점검(모든 파일 통과): id 중복 없음, 조각·겹침 파일의 id 순서가 `sample_key.parquet`의 shard_pos·overlap_pos와 같음, 세기 0~3 정수, MOCK ≥ 1 ↔ mock_target, pred = 0 ↔ pred_target null, conf 1~3, 검수지 id 순서가 `review_label_key.parquet`와 같음.
- κ는 같은 계열 AI 두 번의 일치다. 같은 지침으로 같은 방식의 실수를 할 수 있어 타당성 확인은 사용자 검수 200건과의 비교가 맡는다.
- ENVY(22단위)·REGRET(64단위)·불안한 기쁨(9단위)은 표본이 작다. 이중 라벨 600단위 안 ENVY는 1차 9·2차 8단위라 κ 구간이 넓다(0.57~1.00).
- 조롱은 세기 1(가벼운 비꼼)이 대부분이라, 조롱 지표를 쓸 때 세기 ≥ 2 판을 함께 보는 편이 1차 7범주와 맞대기 쉽다.
- 가격·지수·수익 자료는 읽지 않았고 창(하루)별 특징도 만들지 않았다.
- 집계 코드는 세션 임시 폴더(`scratchpad/nine_batchA.py`, `nine_batchA_report.py`)에 있고 저장소에는 넣지 않았다.
