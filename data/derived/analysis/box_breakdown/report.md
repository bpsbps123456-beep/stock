## 1. 질문과 정의 (BRIEF 그대로, 바꾼 것 없음)

- **사건**
  - L_N(t)는 직전 N일 최저 저가다(N = 20·40·60).
  - 이탈은 종가(t) < L_N이다.
  - 같은 종목에서 10거래일 안에 이어진 이탈은 한 사건으로 센다.
- **진입과 청산**
  - t+1 정규장 시가에 공매도한다.
  - 종가가 L 위로 돌아오면 다음 시가에 청산하고, 아니면 t+10 종가에 청산한다.
  - 비용은 왕복 0.10%이고 대차 비용은 넣지 않았다.
- **분류(설명용, t 뒤 가격을 쓴다)**
  - 진짜: L 위 종가가 나오기 전에 t+10 안에서 L − 2·ATR에 먼저 닿는다.
  - 가짜: t+5 안에 L 위 종가가 나오고, 그때까지 L − 1·ATR에 닿지 않는다.
- **판정**
  - 앞 구간(2026-01-02~05-29)에서 상위 10칸을 고른다. 켜짐 15건·8일 이상인 칸만 대상이다.
  - 뒤 구간(06-01~09-29) 통과 조건: 차이 > 0, 날짜 묶음 t ≥ 2, 날짜 순열 p < 0.05, 켜진 사건 평균 > 0.
  - 2025는 같은 방향인지만 본다.
  - 초과 공매도 손익은 보조로 보고만 하고 통과 조건에는 쓰지 않는다. 날짜 고정 특징에서는 구조적으로 0에 가깝다(점검 18).
- 개별 종목 손익은 공매도 대리(−주가 수익)다. 실제 실행 수단은 6절에서 따로 잰다.

### b4 '하루 늦춘 값' 표기 정정 (점검 2)

- **무엇이 틀렸나:** b4.md의 `*_lag1`은 '하루 미래(누출) 값'이었다.
  - `attach(lag=1)`은 t+2에 놓인 값, 곧 t+1 저녁에 공개된 값을 붙인다.
  - 원자료 날짜가 t보다 뒤인 행이 3,492/3,543개다 [verify_b4_flow_timing.json `b4_lag1_flag_timing`].
  - 그래서 "하루 늦추면 앞 구간 N20이 +0.5%p로 사라진다"는 누출 값이었다.
- **다시 계산:** 원자료 날짜 ≤ t−1(`lag=-1`)로 다시 계산했다. 시점 위반은 23특징 모두 0건이다 [review_b4_stale_summary.json `timing_violations_w_ge_t`].
