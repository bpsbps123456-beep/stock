# 야간 데스크 (개인 매매 보조)

> 활성 기준일: **2026-10-08**  
> 사용자가 고른 규칙을 매일 따라 매매하게 돕는 로컬 화면의 규칙 정본이다. AI 산업 지도(기존 AI 탐방) 탭은 §8, 거인의 어깨 탭은 §9, 급락 후 담기 탭은 §10이다. 신호에 쓰는 PDF·날짜 규칙은 `docs/etf_system.md`를 따른다.

## 1. 범위와 원칙

- 사용자 포트폴리오의 목표 비중·주문 수량은 시스템에서 이 데스크만 계산한다(2026-09-27 사용자 결정). Path-B 브리핑, 관찰군, `etf trades`, 전략 연구 산출물에는 주문표를 넣지 않는다.
- 데스크는 주문을 내지 않는다. 사용자가 증권사에서 직접 주문하고 체결 결과를 기록한다.
- 미국 상장 주식만 다룬다. 아래 사용자 매매 조건은 시스템 전체의 정본이다.
  - 수수료: 매수·매도 0원(2026-09-27·29 사용자 확인). 호가·환전 스프레드는 따로 남을 수 있다.
  - 주문 가능 시간: 한국시간 08:00~24:00(2026-09-28 사용자 정정, 이전 기록은 08:00~23:00). 미국 프리장과 주간거래(한국 낮)에도 매매할 수 있다(2026-09-29).
  - 자는 동안(00~08시)에는 현재가보다 높은 지정가 매도와 낮은 지정가 매수를 걸어 둔다. 손절(스탑) 주문도 걸어 둘 수 있다(2026-10-10 사용자 확인). 매수가 체결되기 전에 손절을 함께 거는 주문과 애프터마켓 체결은 확인하지 않았다.
- 전략은 **7종목 하나**다(2026-09-27 사용자 결정, Codex 집중도 연구 #774). 비교용으로 두었던 혼합·H6e·#239120은 뺐다.
- 규칙은 사용자 결정으로만 바꾼다. 연구 결과만으로 바꾸지 않는다. 바꾸면 이 문서와 `docs/operations_changelog.md`에 기록하고 §6 검증을 다시 통과시킨다.

## 2. 실행

```bash
py -m desk open               # 루트 야간데스크.cmd·바탕화면 '야간 데스크'와 같음: 켜져 있으면 화면만, 아니면 켜고 화면을 연다
py -m desk serve              # 서버만 이 창에서 띄움 — http://127.0.0.1:8321/
py -m desk validate           # §6 검증
py -m unittest tests.test_desk tests.test_desk_launch
```

- 더블클릭(`야간데스크.cmd` 또는 바탕화면 바로 가기 `야간 데스크`)은 `py -m desk open`이다(2026-10-06 사용자 요청: 더블클릭하면 페이지가 떠야 함).
  - 데스크가 켜져 있으면 화면만 연다. 꺼져 있으면 서버를 작업 표시줄에 최소화된 새 창으로 띄우고, 응답하면 브라우저를 연 뒤 실행 창은 스스로 닫힌다. 60초 안에 응답이 없으면 안내를 남기고 멈춘다.
  - 서버는 포트를 먼저 열고 가격·7종목 신호는 뒤에서 계산한다. 화면이 먼저 뜨고 계산이 끝나면 채워진다(그동안 화면에 계산 중 안내). 예전에는 계산이 끝나야 브라우저를 열어, 가격을 새로 받는 날엔 검은 창만 보였다.
  - 서버 창은 `--launcher`로 띄워 Ctrl+C를 무시한다. 콘솔에서 선택 없이 누른 Ctrl+C는 복사가 아니라 종료라서, 한 번 데스크가 저녁에 꺼졌다. 끄려면 서버 창(제목 '야간 데스크 — 이 창을 닫으면 꺼집니다')을 닫는다. 서버가 꺼져 있으면 화면 맨 위에 안내가 뜨고, 다시 켜지면 저절로 연결된다.
- 같은 매매 기록을 쓰는 데스크가 이미 켜져 있으면 새로 띄우지 않고 그 창을 연다. 포트는 배타적으로 잡는다. Windows에서 SO_REUSEADDR를 쓰면 두 서버가 같은 포트를 나눠 가져 요청이 갈라진다.
- 평일 21:45 KST 이후 `내 계좌·주문` 제목 옆의 `펀드 자료 갱신`은 `py gbrc.py briefing`을 실행해 그날 PDF를 받는다.
- 날짜 없는 `py gbrc.py briefing`은 `## 핵심 결론` 첫 블록으로 `[내 7종목 점검]`을 넣는다(`desk/digest.py`, 단독 출력은 `py -m desk digest`). 이번 주 7종목의 모멘텀 순위, 두 펀드 실매매, 유지선·편출 메모, 대기 종목, 재조정 미리보기, 모델 낙폭·멈춤 규칙 상태를 보여 준다. 비중·주문 수량과 개인 계좌 정보는 넣지 않는다.
- 테스트 서버는 `DESK_JOURNAL_DIR=<임시 폴더>`와 `--port=7999`로 띄워 사용자 데스크(8321)·실제 기록과 분리한다. 쓰기 전에 `/api/ping`의 journal 경로를 확인한다.

### 2.1 화면 구성 (2026-10-07)

- 네 탭은 화면 전체 폭을 사용한다. 상단에는 탭과 테마 전환, 각 탭에는 스크롤해도 남는 구역 바로가기가 있다. 탭으로 돌아오면 그 탭의 마지막 읽던 위치를 복원한다.
- `내 계좌·주문`은 주문 안내 옆에 계좌 요약·보유 종목·점검 신호를 모은다. 시세·펀드 자료 갱신은 제목 옆에 둔다. 전략 모의 성과와 종목·계좌 차트, 매매 기록은 아래에서 확인한다.
- 긴 표는 표 안에서 스크롤하고 제목 행을 고정한다. 거인의 어깨는 분야·회사 이름도 가로 스크롤 중에 유지한다. 좁은 화면에서는 표·지도·비교 차트를 옆으로 스크롤하며, 그림 이름표 크기는 §8 기준을 유지한다.
- 운용 규칙·계산 설명·출처는 화면 아래 접을 수 있는 설명란에 보존한다. 점검 신호와 자료 경고는 설명란 밖에 표시한다. UI 변경은 계산·매매 규칙을 바꾸지 않으며 §6 성과 재생 대상이 아니다.

### 2.2 화면 명칭 (2026-10-07)

사용자 요청에 따라 탭·제목·바로가기·안내 문장에서 같은 명칭을 쓴다. 전체 이름 `야간 데스크`와 탭 이름 `거인의 어깨`는 유지한다.

| 구역 | 화면 명칭 | 의미 |
|---|---|---|
| 계좌·주문 탭 | 내 계좌·주문 | 실제 계좌, 주문 안내, 체결 기록 |
| 공급망 탭 | AI 산업 지도 | AI 공급망과 대표 기업. 기존 AI 탐방과 같은 화면 |
| 강세·수급 탭 | 거인의 어깨 · AI 섹터·주도주 분석 | 사업 분야와 종목의 회복·강세·수급 비교 |
| 급락 탭 | 급락 후 담기 · 급락 종목 관찰·3분봉 | 그날 크게 빠진 종목, 3분봉 다시 보기, 과거 비슷한 경우의 결과 |
| 과거 전략 성과 | 7종목 전략 모의 성과 | 규칙과 과거 자료로 계산한 성과. 실제 내 계좌 성과와 구분 |
| 거인의 어깨 분류 기준 | 사업 분야 / 대표 사업 분류 / 산업 대분류 | 지도상의 여러 역할 / 회사별 대표 사업 한 곳 / 큰 산업 단위 |
| 시장 폭 지표 | 전고점 근접 비율 | 전고점 -10% 이내인 종목의 비율 |
| 수급 표 | 펀드 매매·투자자 수급 | 두 펀드 실매매와 시장별로 확인 가능한 투자자·공매도 자료 |

`회복 등급`은 기존 계산 의미를 유지한다. 단순한 투자 추천 등급으로 이름을 바꾸지 않는다.

### 2.3 휴대폰·다른 기기에서 보기 (2026-10-07)

사용자 결정: 데스크를 밖에서 실시간으로 볼 때는 Vercel 배포 대신 Tailscale 내 기기망(tailnet)으로 이 PC의 데스크에 접속한다. 계산이 PC(매매 기록·펀드 PDF·시세 계산)에 있어서 Vercel은 보기 전용 지연 업로드(무료 플랜 하루 배포 100회)나 전면 재작성(함수 최대 60초)이 필요했다.

| 항목 | 내용 |
|---|---|
| 연결 | PC에 Tailscale(서비스 자동 시작)을 설치하고 로그인했다. `tailscale serve --bg 8321`이 `https://<PC 이름>.<tailnet>.ts.net/`을 `http://127.0.0.1:8321`에 잇는다. 재부팅해도 유지되며, 주소는 `tailscale serve status`로 확인한다 |
| 휴대폰 | Tailscale 앱에 같은 계정으로 로그인한 뒤 그 주소를 연다. 시세·펀드 자료 갱신과 매매 기록도 PC에서와 같이 된다 |
| 금지 | `tailscale funnel`(인터넷 공개)은 쓰지 않는다. 데스크에는 로그인이 없어서 내 기기망 밖으로 열면 매매 기록이 노출된다 |
| 조건 | PC가 켜져 있고 데스크 서버가 실행 중이어야 한다. 이 PC는 입력 없이 8시간이 지나면 절전한다(2026-10-07 측정) |
| 코드 변경 뒤 | 정적 파일은 바로 반영되고 `/api/*`는 서버를 다시 켜야 반영된다. 원격 화면도 같다 |
| 끄기 | `tailscale serve --https=443 off` |

## 3. 7종목 규칙

| 단계 | 규칙 |
|---|---|
| 후보 | 그 미국 거래일보다 앞선 날짜의 최신 TIME PDF에 있는 미국 상장 보유종목 |
| 순위 | 전일 종가까지의 120거래일 수정주가 수익률 |
| 선택 | 7종목. 지난주 7종목은 12위 안이면 유지하고, 빈자리는 높은 순위부터 채운다 |
| 기본 비중 | 고른 7종목의 TIME NAV 비중에 비례 |
| 상한 | 한 종목 25%, 같은 섹터 60%, 반도체 합계 60%(`watchlist.py` 섹터 AI 반도체·메모리·반도체 장비·반도체 장비(적자)·반도체(적자)·반도체 소재와 미분류 전부) |
| 넘친 몫 | 고른 종목 안에서 비례로 나누고, 모두 상한에 걸리면 현금으로 둔다. 100%로 다시 맞추지 않는다 |
| 교체 | 매주 첫 미국 거래일 개장가. 주중에는 거래하지 않는다 |

- 신호 시점: 그 미국 거래일보다 앞선 날짜의 PDF와 전일 종가만 쓴다. PDF D는 D-1 KRX 바스켓이며 21:45 KST에 공개된다(`docs/etf_system.md` §3). 미국 휴장 다음 날에는 한국장이 연 날의 PDF를 쓰므로 Codex 연구의 "공시 1일 지연"보다 PDF가 하루 새롭다.
- 섹터는 `watchlist.resolve_sector`로 찾고 기록된 티커 변경(SATS→ECHO)과 원천 표기(MOG/A)를 함께 조회한다. 코드 정본은 `desk/strategies.py`다.

## 4. 주문 계산과 매매 기록

- 목표 금액 = 목표 비중 × (보유 평가액 + 양수 현금). 평가는 현재가(장전·장후를 포함한 1분 시세, 없으면 전일 종가)로 한다.
- 목표와의 차이가 허용 오차(기본 계좌의 2%) 이상이면 매수·매도한다. 목표에서 빠진 보유는 전량 매도하고 나머지는 유지다. 소수 주와 정수 주를 함께 표시한다. 주중에는 모델의 현재 보유를 목표로 삼는다. 코드 정본은 `desk/state.py`다.
- 매매 기록은 `data/journal/trades.json`(Git 제외 개인 데이터)에 입금·출금·매수·매도로 남긴다. 평균단가 방식이며 보유보다 많이 파는 기록은 거부한다. 계좌 수익·낙폭은 입출금을 걷어낸 시간가중 수익 지수로 잰다. 코드 정본은 `desk/journal.py`다.
- 모델은 종가로 평가해 원화로 바꾼다. TIME ETF는 한국에서 거래되므로 미국 거래일 t를 그다음 KRX 종가와 비교한다. 같은 날짜 종가를 쓰면 ETF가 미국장을 하루 늦게 반영해 비교가 틀어진다.

## 5. 멈춤·점검 규칙 (2026-09-27 고정)

성과 부진만으로는 멈추지 않는다. 검증한 범위를 벗어날 때만 행동을 바꾼다. 기준값은 실제 낙폭을 겪기 전에 정했으므로 사후에 고치지 않는다. 코드 정본은 `desk/alerts.py`다.

| 수준 | 조건 | 행동 |
|---|---|---|
| 주의 | 모델이 최근 20거래일 TIME ETF보다 10%p 넘게 뒤짐 | 멈추지 않는다 |
| 경고 | 내 계좌(입출금 보정) 또는 모델 낙폭이 2026년 최악 -30.3%보다 5%p 넘게 깊음(-35.3%) | 매매 규칙은 따르되 새 돈을 넣지 않고 투자 금액을 다시 정한다 |
| 경고 | 모델이 최근 120거래일 TIME ETF보다 못함 | 이 전략을 계속 쓸지 재평가한다 |

근거(2026-09-27 측정, 수수료 0·개장가 체결, ETF는 다음 KRX 종가로 맞춤):

- 2026년 7종목의 20거래일 최저 격차는 -8.1%p(5/7)였고, 120거래일 격차는 한 번도 0 아래로 내려가지 않았다.
- 2023~2025년(주간 PDF, 규칙 고정)에 7종목은 TIME ETF의 0.89~1.09배였고 120거래일 격차가 음수인 날이 39~43%였다. 그때 20거래일 -10%p 규칙으로 ETF에 옮겼다면 +244.7%가 +112.9%로 줄었다(공시 +1일은 +205.1%→+95.9%). 60거래일 0 기준도 +84.2%·+89.0%로 줄었고, 현금으로 옮기면 더 나빴다.
- 2023~2025년 보유 118종목 중 56개가 `watchlist.py`에서 미분류라 그 기간에는 상한이 과하게 걸린다. 상한을 빼면 1.18~1.51배였다.

## 8. AI 산업 지도 (기존 AI 탐방, 2026-10-05)

데스크 상단 탭 `AI 산업 지도`는 데스크(투자회사)가 AI 공급망의 회사들을 가장 기초(전력·소재·장비)부터 완제품(AI 모델)과 그 서비스까지 순서대로 방문하는 참고 화면이다. 목적은 두 가지다: 투자할 때 각 회사가 AI 전체에서 맡는 일과 부서별 대장주를 알고, AI의 공정 흐름을 이해한다(2026-10-05 사용자 요청). 매매 신호·주문·기록 코드를 바꾸지 않으므로 §6 재검증 대상이 아니다.

### 8.1 갱신 체크리스트 (요청 "AI 산업 지도 갱신" 또는 기존 "AI 탐방 갱신")

1. `as_of` 이후 나온 두 축의 계약·투자·상장 소식을 찾는다. 회사 발표(IR·보도자료·SEC 공시)를 먼저 보고, 없으면 주요 언론을 본다. 보도만 있으면 `보도`, 의향서면 `의향`으로 적는다. 출처 URL이 없으면 넣지 않는다.
2. 상단 배너(미배치 보유, 유니버스 누락, 기준일 경과)를 모두 없앤다. 새 종목은 대표 부서 하나에 넣고, 다른 부서에도 있으면 `main`을 단다. 밖에 둘 종목은 `outside`에 이유와 함께 적는다.
3. 역할(`role`)에 숫자·순위·점유율·"최대"를 넣으면 `src`를 단다. 두 축 계약이 있는 회사는 계약 줄의 출처로 갈음한다. 출처가 없으면 숫자를 빼고 말로 적는다.
4. 부서마다 대장이 바뀌었는지 보고, 근거를 위 대장 규칙대로 적는다.
5. `as_of`를 갱신하고 `py -m unittest tests.test_tour tests.test_scenes`를 통과시킨다. `test_tour`가 출처·날짜·방문 순서·대표 부서·대장 근거·유니버스 포함·기호 변환을, `test_scenes`가 그림에 없는 분야·이름표 겹침·낡은 이름표를 막는다.
   - 분야 이름·대표·병목을 바꿨으면 `py -m desk.scenes.layout`을 실행한다(블렌더 불필요, 1초).
   - 그림이 있는 방문지에 분야를 새로 넣으면 `desk/scenes/blender/`의 해당 장면 모듈에 물체(`zone` 표시)와 `K.spot(분야)`를 더하고 `"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P desk/scenes/blender/build.py -- <패널>`로 다시 렌더한 뒤 layout을 실행한다. 빠른 확인은 `--preview --out <임시 폴더>`.
6. 테스트 서버(`DESK_JOURNAL_DIR=<임시 폴더>`, `--port=7999`)로 두 테마와 좁은 화면을 확인한다. JSON은 요청마다 다시 읽지만, 파이썬 파일을 고쳤으면 서버를 다시 띄운다.

- **기준 구간**: SOXX의 최근 252거래일에서 가장 깊었던 하락(고점→저점)이다. 새 고점이 나와도 더 깊은 하락이 오기 전까지 유지된다. 2026-10-05 현재 6/22→7/29(-29.0%)다. 아시아 종목은 그 날짜 또는 직전 거래일 종가를 쓴다.
- **렌즈**(정렬·차트 기준): 저점 이후(기본), 최근 1개월(21거래일), 고점 대비(급락 전 고점일 종가 대비 순수익률), 급락 구간. 저점 이후에는 많이 빠진 종목이 크게 튀는 효과가 섞이므로 고점 대비와 함께 본다.
- **사업 분야**(2026-10-07 사용자 요청): AI 산업 지도의 부서를 비교 단위로 사용하며, `AI_UNIVERSE`에 있는 상장 종목만 연결한다. 기본 화면은 사업 분야이고, 기존 대표 소분류(`대표 사업 분류`)와 대분류(`산업 대분류`)도 전환할 수 있다. 새 명단을 복제하거나 유니버스를 늘리지 않는다.
  - CPU·GPU, 배전·냉각처럼 역할이 겹치면 회사가 여러 분야에 들어간다. 분야마다 회사당 한 번만 집계하고, 전체 종목 비교에서도 중복을 없앤다. 분야별 종목 수나 펀드 건수는 서로 더하지 않는다. 수익률은 회사 주가 기준으로, 특정 제품 사업만의 수익률은 아니다.
  - 분야 회복 등급은 전체·S·A·B·C·D·미산정으로 필터링하고 분야·상위 분류 이름으로 검색한다. 분야 표와 수급 표가 같은 분야를 표시하며, 남은 분야가 없으면 빈 결과를 안내한다. ‘미산정’은 D와 다르다.
  - 종목 비교 범위는 ‘선택한 분야’, 분야 등급·검색 필터에 남은 ‘표시된 모든 분야’, 분야 필터와 무관한 ‘전체 AI 종목’이다. 종목 회복 등급과 회사명·종목 코드 검색을 별도로 적용한다. ‘전체 S등급 종목 보기’는 종목 검색을 지우고 전체 AI 종목의 S종목을 바로 보여 준다. 차트도 같은 종목을 강조한다.
  - 1700px 이상은 분야·종목 표를 나란히 놓고, 더 좁으면 분야 행을 선택할 때 종목 표로 이동한다. 표의 지표 전환은 열 표시만 바꾸며 모든 수치는 ‘모든 지표’에서 확인할 수 있다. 정렬 방향과 관계없이 자료 없는 종목은 끝에 둔다.

### 10.1 알려진 한계

- 분봉 연구는 두 달(2026-08-10~10-06)뿐이다. 두 조건은 여러 후보 중 고른 칸이라 우연일 수 있다.
- 생존 편향: 지금 상장된 종목만으로 연구했다. 급락 뒤 상장폐지된 종목이 빠져 결과가 실제보다 좋게 나오는 쪽이다.
- Yahoo 1분봉은 최근 30일(한 요청 8일)만 있어 그보다 오래된 날은 다시 볼 수 없다. 3분봉은 1분봉을 묶은 것이다.
- 지난 날짜 재생에는 실적 여부를 표시하지 않는다. 뉴스는 나스닥 종목 뉴스 최신 8건이라 지난 날짜의 뉴스가 아닐 수 있다.
- 체결은 봉 종가로 가정한다. 급락주 장전 호가는 0.5~2% 벌어질 수 있고 스프레드는 반영하지 않는다.
- 뉴스 종류(기소·보고서·벌금)는 자동으로 분류하지 않는다.
