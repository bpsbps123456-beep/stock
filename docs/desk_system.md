# 야간 데스크 (개인 매매 보조)

> 활성 기준일: **2026-10-12**  
> 사용자가 고른 규칙을 매일 따라 매매하게 돕는 로컬 화면의 규칙 정본이다. AI 산업 지도(기존 AI 탐방) 탭은 §8(Vercel 휴대폰 설명 사이트는 §8.3), 거인의 어깨 탭은 §9, 급락 후 담기 탭은 §10, 추세 등급 탭은 §11, 개미 지수(1단계 수집, 탭은 아직 없음)는 §12(옵션 심리 연구 §12.2, 옵션 × 헤지펀드 종합 §12.3), 뉴스 근거 탭은 §13이다. 신호에 쓰는 PDF·날짜 규칙은 `docs/etf_system.md`를 따른다.

## 1. 범위와 원칙

- 사용자 포트폴리오의 목표 비중·주문 수량은 시스템에서 이 데스크만 계산한다(2026-09-27 사용자 결정). Path-B 브리핑, 관찰군, `etf trades`, 전략 연구 산출물에는 주문표를 넣지 않는다.
- 데스크는 주문을 내지 않는다. 사용자가 증권사에서 직접 주문하고 체결 결과를 기록한다.
- 미국 상장 주식만 다룬다. 아래 사용자 매매 조건은 시스템 전체의 정본이다.
  - 수수료: 매수·매도 0원(2026-09-27·29 사용자 확인). 호가·환전 스프레드는 따로 남을 수 있다.
  - 주문 가능 시간: 한국시간 08:00~24:00(2026-09-28 사용자 정정, 이전 기록은 08:00~23:00). 미국 프리장과 주간거래(한국 낮)에도 매매할 수 있다(2026-09-29).
  - 자는 동안(00~08시)에는 현재가보다 높은 지정가 매도와 낮은 지정가 매수를 걸어 둔다. 손절(스탑) 주문도 걸어 둘 수 있다(2026-10-10 사용자 확인). 매수가 체결되기 전에 손절을 함께 거는 주문과 애프터마켓 체결은 확인하지 않았다.
- 전략은 **7종목 하나**다(2026-09-27 사용자 결정, Codex 집중도 연구 #774). 비교용으로 두었던 혼합·H6e·#239120은 뺐다. 반도체 한도는 2026-10-10 사용자 결정으로 #774의 60%에서 50%로 낮췄다(§3).
- 규칙은 사용자 결정으로만 바꾼다. 연구 결과만으로 바꾸지 않는다. 바꾸면 이 문서와 `docs/operations_changelog.md`에 기록하고 §6 검증을 다시 통과시킨다.

## 2. 실행

```bash
py -m desk open               # 루트 야간데스크.cmd·바탕화면 '야간 데스크'와 같음: 켜져 있으면 화면만, 아니면 켜고 화면을 연다
py -m desk serve              # 서버만 이 창에서 띄움 — http://127.0.0.1:8321/
py -m desk validate           # §6 검증
py -m unittest tests.test_desk tests.test_desk_launch
```

- 더블클릭(`야간데스크.cmd` 또는 바탕화면 바로 가기 `야간 데스크`)은 `py -m desk open`이다(2026-10-06 사용자 요청: 더블클릭하면 페이지가 떠야 함).
  - 데스크가 켜져 있으면 화면만 연다. 꺼져 있으면 서버를 작업 표시줄에 최소화된 새 창으로 띄우고, 응답하면 브라우저를 연 뒤 실행 창은 스스로 닫힌다. 60초 안에 응답이 없으면 안내를 남기고 멈춘다.
  - 서버는 포트를 먼저 열고 가격·7종목 신호는 뒤에서 계산한다. 화면이 먼저 뜨고 계산이 끝나면 채워진다(그동안 화면에 계산 중 안내). 예전에는 계산이 끝나야 브라우저를 열어, 가격을 새로 받는 날엔 검은 창만 보였다.
  - 서버 창은 `--launcher`로 띄워 Ctrl+C를 무시한다. 콘솔에서 선택 없이 누른 Ctrl+C는 복사가 아니라 종료라서, 한 번 데스크가 저녁에 꺼졌다. 끄려면 서버 창(제목 '야간 데스크 — 이 창을 닫으면 꺼집니다')을 닫는다. 서버가 꺼져 있으면 화면 맨 위에 안내가 뜨고, 다시 켜지면 저절로 연결된다.
- 같은 매매 기록을 쓰는 데스크가 이미 켜져 있으면 새로 띄우지 않고 그 창을 연다. 포트는 배타적으로 잡는다. Windows에서 SO_REUSEADDR를 쓰면 두 서버가 같은 포트를 나눠 가져 요청이 갈라진다.
- 평일 21:45 KST 이후 `내 계좌·주문` 제목 옆의 `펀드 자료 갱신`은 `py gbrc.py briefing`을 실행해 그날 PDF를 받는다.
- 날짜 없는 `py gbrc.py briefing`은 `## 핵심 결론` 첫 블록으로 `[내 7종목 점검]`을 넣는다(`desk/digest.py`, 단독 출력은 `py -m desk digest`). 이번 주 7종목의 모멘텀 순위, 두 펀드 실매매, 유지선·편출 메모, 대기 종목, 재조정 미리보기, 모델 낙폭·멈춤 규칙 상태를 보여 준다. 비중·주문 수량과 개인 계좌 정보는 넣지 않는다.
- 테스트 서버는 `DESK_JOURNAL_DIR=<임시 폴더>`와 `--port=7999`로 띄워 사용자 데스크(8321)·실제 기록과 분리한다. 쓰기 전에 `/api/ping`의 journal 경로를 확인한다.

### 2.1 화면 구성 (2026-10-07)

- 다섯 탭은 화면 전체 폭을 사용한다(휴대폰 폭에서는 탭 줄이 두 줄이 된다). 상단에는 탭과 테마 전환, 각 탭에는 스크롤해도 남는 구역 바로가기가 있다. 탭으로 돌아오면 그 탭의 마지막 읽던 위치를 복원한다.
- `내 계좌·주문`은 주문 안내 옆에 계좌 요약·보유 종목·점검 신호를 모은다. 시세·펀드 자료 갱신은 제목 옆에 둔다. 전략 모의 성과와 종목·계좌 차트, 매매 기록은 아래에서 확인한다.
- 긴 표는 표 안에서 스크롤하고 제목 행을 고정한다. 거인의 어깨는 분야·회사 이름도 가로 스크롤 중에 유지한다. 좁은 화면에서는 표·지도·비교 차트를 옆으로 스크롤하며, 그림 이름표 크기는 §8 기준을 유지한다.
- 운용 규칙·계산 설명·출처는 화면 아래 접을 수 있는 설명란에 보존한다. 점검 신호와 자료 경고는 설명란 밖에 표시한다. UI 변경은 계산·매매 규칙을 바꾸지 않으며 §6 성과 재생 대상이 아니다.

### 2.2 화면 명칭 (2026-10-07)

사용자 요청에 따라 탭·제목·바로가기·안내 문장에서 같은 명칭을 쓴다. 전체 이름 `야간 데스크`와 탭 이름 `거인의 어깨`는 유지한다.

| 구역 | 화면 명칭 | 의미 |
|---|---|---|
| 계좌·주문 탭 | 내 계좌·주문 | 실제 계좌, 주문 안내, 체결 기록 |
| 공급망 탭 | AI 산업 지도 | AI 공급망과 대표 기업. 기존 AI 탐방과 같은 화면 |
| 강세·수급 탭 | 거인의 어깨 · AI 섹터·주도주 분석 | 사업 분야와 종목의 회복·강세·수급 비교 |
| 급락 탭 | 급락 후 담기 · 급락 종목 관찰·3분봉 | 그날 크게 빠진 종목, 3분봉 다시 보기, 과거 비슷한 경우의 결과 |
| 추세 탭 | 추세 등급 · 두 펀드 보유 종목 이평선 추세 | 두 펀드 보유 종목 전부의 지금 가격·이평선 추세를 S~D로 나눈 상태(§11) |

| 수급 표 | 펀드 매매·투자자 수급 | 두 펀드 실매매와 시장별로 확인 가능한 투자자·공매도 자료 |

`회복 등급`은 기존 계산 의미를 유지한다. 단순한 투자 추천 등급으로 이름을 바꾸지 않는다. `추세 등급`(§11)은 급락에서 되찾은 정도가 아니라 오늘의 이평선 추세 상태라서 회복 등급과 계산이 다르다. 두 등급을 한 표에 섞지 않는다.

### 2.3 휴대폰·다른 기기에서 보기 (2026-10-07)

사용자 결정: 데스크를 밖에서 실시간으로 볼 때는 Vercel 배포 대신 Tailscale 내 기기망(tailnet)으로 이 PC의 데스크에 접속한다. 계산이 PC(매매 기록·펀드 PDF·시세 계산)에 있어서 Vercel은 보기 전용 지연 업로드(무료 플랜 하루 배포 100회)나 전면 재작성(함수 최대 60초)이 필요했다. 데스크는 계속 Vercel에 올리지 않는다. Vercel에는 개인 자료 없이 AI 산업 지도만 담은 설명 사이트(§8.3)만 올린다(2026-10-10 사용자 요청).

| 항목 | 내용 |
|---|---|
| 연결 | PC에 Tailscale(서비스 자동 시작)을 설치하고 로그인했다. `tailscale serve --bg 8321`이 `https://<PC 이름>.<tailnet>.ts.net/`을 `http://127.0.0.1:8321`에 잇는다. 재부팅해도 유지되며, 주소는 `tailscale serve status`로 확인한다 |
| 휴대폰 | Tailscale 앱에 같은 계정으로 로그인한 뒤 그 주소를 연다. 시세·펀드 자료 갱신과 매매 기록도 PC에서와 같이 된다 |
| 금지 | `tailscale funnel`(인터넷 공개)은 쓰지 않는다. 데스크에는 로그인이 없어서 내 기기망 밖으로 열면 매매 기록이 노출된다 |
| 조건 | PC가 켜져 있고 데스크 서버가 실행 중이어야 한다. 이 PC는 입력 없이 8시간이 지나면 절전한다(2026-10-07 측정) |
| 코드 변경 뒤 | 정적 파일은 바로 반영되고 `/api/*`는 서버를 다시 켜야 반영된다. 원격 화면도 같다 |
| 끄기 | `tailscale serve --https=443 off` |

## 3. 7종목 규칙

| 단계 | 규칙 |
|---|---|
| 후보 | 그 미국 거래일보다 앞선 날짜의 최신 TIME PDF에 있는 미국 상장 보유종목 |
| 순위 | 전일 종가까지의 120거래일 수정주가 수익률 |
| 선택 | 7종목. 지난주 7종목은 12위 안이면 유지하고, 빈자리는 높은 순위부터 채운다 |
| 기본 비중 | 고른 7종목의 TIME NAV 비중에 비례 |
| 상한 | 한 종목 25%, 같은 섹터 60%, 반도체 합계 50%(`watchlist.py` 섹터 AI 반도체·메모리·반도체 장비·반도체 장비(적자)·반도체(적자)·반도체 소재와 미분류 전부). 반도체는 2026-10-10 사용자 결정으로 #774의 60%에서 낮췄다(아래) |
| 넘친 몫 | 고른 종목 안에서 비례로 나누고, 모두 상한에 걸리면 현금으로 둔다. 100%로 다시 맞추지 않는다 |
| 교체 | 매주 첫 미국 거래일 개장가. 주중에는 거래하지 않는다 |

- 신호 시점: 그 미국 거래일보다 앞선 날짜의 PDF와 전일 종가만 쓴다. PDF D는 D-1 KRX 바스켓이며 21:45 KST에 공개된다(`docs/etf_system.md` §3). 미국 휴장 다음 날에는 한국장이 연 날의 PDF를 쓰므로 Codex 연구의 "공시 1일 지연"보다 PDF가 하루 새롭다.
- 섹터는 `watchlist.resolve_sector`로 찾고 기록된 티커 변경(SATS→ECHO)과 원천 표기(MOG/A)를 함께 조회한다. 코드 정본은 `desk/strategies.py`이고, 상한 값은 `desk/config.py`의 `RULE`이다(화면 문구도 이 값을 읽는다).
- 반도체 한도 50%(2026-10-10): 같은 날 쟀던 데스크 규칙 위 변형 20개 중 유일하게 '관찰'로 남은 것을 사용자가 채택했다(`data/derived/analysis/rsi_breakout/report.md` '추가 2').
  - 2026-01-02~10-09 시가 경로(USD) 기준으로 수익은 그대로였다(+223.7%, 60%는 +222.1%). 최대 낙폭은 −20.3%로 줄었다(60%는 −23.7%).
  - 잰 값은 40·45·50·55·60% 다섯 개다. 한도를 낮출수록 낙폭이 줄었다(55% −22.0%, 45% −18.6%). 40%(−18.7%)에서는 더 줄지 않았고 1~5월 수익이 13.7%p 낮았다. 근거는 7월 반도체 급락 한 번이다.
  - 연도 내 전방 검증: 1/2~5/29 +209.4%(60% +207.0%), 6/1~10/9 +4.6%(60% +4.9%)였다. 낙폭 개선은 뒤 구간(7월)에서 나왔고, 수익은 두 구간 모두 거의 같았다.
  - 9/1~10/9는 60%보다 1%p 덜 벌었다(+13.6% 대 +14.6%).
  - 위 숫자는 TIME 미분류 56개 분류(2026-10-10) 전 값이다. 분류 뒤 같은 계산은 전체 +220.4%(60% +219.9%), 1/2~5/29 +206.2%(+205.0%), 6/1~10/9 +4.6%(+4.9%), 낙폭 −20.3%(−23.7%)다.
  - 넘친 몫은 고른 비반도체 종목에 비례로 간다. 그래서 반도체가 몰린 주에는 DELL·SNOW 같은 종목이 25%까지 커지거나 현금이 생긴다.
- 순위 표의 `세부 섹터`(2026-10-10 사용자 요청)는 표시용이다. `watchlist.resolve_subsector`로 `AI_UNIVERSE` 소분류(거인의 어깨 '대표 사업 분류')를 찾는다. 같은 회사의 다른 상장은 `AI_UNIVERSE_ALIASES`로 잇는다(GOOG→GOOGL, SKHY→SK하이닉스).
  - AI 밖 종목(COIN·MELI 등)은 위 섹터를 그대로 보인다.
  - 상한은 계속 위 섹터로 계산한다. 화면에서 이름에 마우스를 올리면 상한 섹터를 보여 준다.

## 4. 주문 계산과 매매 기록

- 목표 금액 = 목표 비중 × (보유 평가액 + 양수 현금). 평가는 현재가(장전·장후를 포함한 1분 시세, 없으면 전일 종가)로 한다.
- 목표와의 차이가 허용 오차(기본 계좌의 2%) 이상이면 매수·매도한다. 목표에서 빠진 보유는 전량 매도하고 나머지는 유지다. 소수 주와 정수 주를 함께 표시한다. 주중에는 모델의 현재 보유를 목표로 삼는다. 코드 정본은 `desk/state.py`다.

## 8. AI 산업 지도 (기존 AI 탐방, 2026-10-05)

데스크 상단 탭 `AI 산업 지도`는 데스크(투자회사)가 AI 공급망의 회사들을 가장 기초(전력·소재·장비)부터 완제품(AI 모델)과 그 서비스까지 순서대로 방문하는 참고 화면이다. 목적은 두 가지다: 투자할 때 각 회사가 AI 전체에서 맡는 일과 부서별 대장주를 알고, AI의 공정 흐름을 이해한다(2026-10-05 사용자 요청). 매매 신호·주문·기록 코드를 바꾸지 않으므로 §6 재검증 대상이 아니다.

- 방문 순서(`no`)는 기초→완제품 순서다. 받는 곳(`from`)은 항상 앞선 방문지이고, 흐름도 자리(`at` = [열, 줄])는 겹치지 않는다.

### 8.1 갱신 체크리스트 (요청 "AI 산업 지도 갱신" 또는 기존 "AI 탐방 갱신")

1. `as_of` 이후 나온 두 축의 계약·투자·상장 소식을 찾는다. 회사 발표(IR·보도자료·SEC 공시)를 먼저 보고, 없으면 주요 언론을 본다. 보도만 있으면 `보도`, 의향서면 `의향`으로 적는다. 출처 URL이 없으면 넣지 않는다.
2. 상단 배너(미배치 보유, 유니버스 누락, 기준일 경과)를 모두 없앤다. 새 종목은 대표 부서 하나에 넣고, 다른 부서에도 있으면 `main`을 단다. 밖에 둘 종목은 `outside`에 이유와 함께 적는다.
3. 역할(`role`)에 숫자·순위·점유율·"최대"를 넣으면 `src`를 단다. 두 축 계약이 있는 회사는 계약 줄의 출처로 갈음한다. 출처가 없으면 숫자를 빼고 말로 적는다.
4. 부서마다 대장이 바뀌었는지 보고, 근거를 위 대장 규칙대로 적는다.
5. `as_of`를 갱신하고 `py -m unittest tests.test_tour tests.test_scenes`를 통과시킨다. `test_tour`가 출처·날짜·방문 순서·대표 부서·대장 근거·유니버스 포함·기호 변환을, `test_scenes`가 그림에 없는 분야·이름표 겹침·낡은 이름표를 막는다.
   - 분야 이름·대표·병목을 바꿨으면 `py -m desk.scenes.layout`을 실행한다(블렌더 불필요, 1초).
   - 그림이 있는 방문지에 분야를 새로 넣으면 `desk/scenes/blender/`의 해당 장면 모듈에 물체(`zone` 표시)와 `K.spot(분야)`를 더하고 `"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P desk/scenes/blender/build.py -- <패널>`로 다시 렌더한 뒤 layout을 실행한다. 빠른 확인은 `--preview --out <임시 폴더>`.
6. 테스트 서버(`DESK_JOURNAL_DIR=<임시 폴더>`, `--port=7999`)로 두 테마와 좁은 화면을 확인한다. JSON은 요청마다 다시 읽지만, 파이썬 파일을 고쳤으면 서버를 다시 띄운다.
7. 설명 사이트(§8.3)를 다시 올린다. 새 방문지·분야·계약 종류·계약 상태가 생겼으면 `aimap/guide.json`에 쉬운 설명을 먼저 더한다(`tests/test_aimap.py`가 빠진 문구를 막는다). 그다음 `py -m aimap deploy`를 실행한다.
8. 저평가 표시(§8.4)는 지도에서 저절로 따라온다. 새 분야가 메모리·저장처럼 경기순환 업종이면 `desk/value.py`의 `CYCLE_ZONES`에 더한다.

- **기준 구간**: SOXX의 최근 252거래일에서 가장 깊었던 하락(고점→저점)이다. 새 고점이 나와도 더 깊은 하락이 오기 전까지 유지된다. 2026-10-05 현재 6/22→7/29(-29.0%)다. 아시아 종목은 그 날짜 또는 직전 거래일 종가를 쓴다.

- **사업 분야**(2026-10-07 사용자 요청): AI 산업 지도의 부서를 비교 단위로 사용하며, `AI_UNIVERSE`에 있는 상장 종목만 연결한다. 기본 화면은 사업 분야이고, 기존 대표 소분류(`대표 사업 분류`)와 대분류(`산업 대분류`)도 전환할 수 있다. 새 명단을 복제하거나 유니버스를 늘리지 않는다.

- **◆ 조건**: ① 소분류의 저점 이후 중앙값이 유니버스 중앙값보다 높다. ② 소분류 안 저점 이후 상위 2위다. ③ 전고점 -10% 이내다(전고점 연구 기준). ④ 최근 50거래일 상승일 거래량이 하락일 거래량 이상이다. 조정값은 `desk/giant.py` 상단에 있다. ◆는 AI 탐방의 ★(분야별 대표 기업)와 다른, 주가·수급 조건이다.

### 9.1 알려진 한계

- ◆ 조건은 2026년 안에서만 재현 검증했다(30개 시점, 20거래일 창이 겹쳐 독립 표본은 약 8개).
  - 상승기(2~6월)에는 유니버스보다 +3.4%p, 반등기(7/30~)에는 -5.9%p였다.
  - 지수가 바닥을 만드는 날에는 '저점 이후'가 모두 0이라 ◆가 빈다(이때 보류 안내). 급락 직후 반등은 많이 빠진 종목이 이끌었다.
  - 사용자는 최근 장세를 따르기로 했다(2026-10-05). 2023~25년 미사용 구간에서 120일 모멘텀(H6e)이 실패한 사례(`docs/operations_changelog.md` 2026-09-27)는 장세가 바뀌면 다시 확인할 근거로만 남긴다.
- 유니버스를 오늘 정했으므로 과거 절대 수익은 부풀려졌다. 바구니끼리 비교할 때만 쓴다.
- 회복 등급은 지금 가격으로 다시 매기는 현재 위치다. 2026-10-10 전방 검증에서 수익률은 맞히지 못했고, 고점 회복만 맞혔다(`data/derived/analysis/grade_persistence/report.md`).
  - 등급 유지: 8/21 등급은 10/8에 28%만 같았다. 10/6→10/8(SOXX -4.4%) 두 거래일에 49종목이 한 단계씩 내려갔다. 소분류 순서는 유지됐다(ρ +0.59).
  - 맞히지 못한 것: 8/21 등급으로 그 뒤 수익률, 구간 최대 낙폭, 장중 -3% 밀린 날의 종가 회복, 종가 위치를 맞히지 못했다(S·A 대 C·D: 수익률 +14.0% 대 +14.9%, 장중 회복 50% 대 50%).
  - 맞힌 것: 높은 등급은 구간 고점 근처를 지켰다. 구간 고점 대비 S·A -2.3%, C·D -5.7%(p 0.02)였다. 미국 종목은 사전 60거래일 SOXX 베타를 맞춘 뒤에도 효과가 남았다(ρ +0.26→+0.34, p 0.002). 10/6 등급은 10/8까지의 하락폭도 맞혔다(베타를 맞춘 뒤 ρ +0.24, p 0.03).
  - 해석: 최악의 순간에는 비슷하게 빠지지만 고점으로 더 빨리 돌아왔다. 등락 폭이 작아서만은 아니다.

| 가격 캐시 | `data/derived/desk/news_prices.json`. 수집 시각·출처·종가 날짜를 표시한다. 최초 설치에서 비어 있으면 ‘가격 갱신’ 또는 CLI로 수집한다. 실패 시 이전 자료와 오류를 함께 표시한다. 가격 갱신은 기사 수집이 아니다 |
| 초기 사례·검증 범위 | 2026년 7월·10월 2국면, 기사 6건. 공개 시각이 확인된 4건은 비교 가능하고 2건은 시각 미확인이다. 완료된 7월 사례는 1국면이며 탐색 조합 0개, 최적화 임계값 0개다. 바닥 확률·적중률로 환산하지 않는다 |
| 전방 기록 | 새 기사를 확인하면 이후 가격을 보기 전에 사실·해석·지지/반대·다음 확인 조건을 원장에 고정한다. 1·3·5일 후 같은 화면에서 복기한다. 7월 사후 분석으로 고른 해석이 10월에 이미 검증됐다고 주장하지 않는다 |
| 적용 범위 | 관찰 기능이다. `Desk` 신호·비중·주문 엔진과 ETF-only 브리핑 출력에 연결하지 않는다. 향후 매매 규칙 채택은 새 기간 검증과 사용자 결정을 따른다 |
| 검증 | `py -m desk news validate`, `py -m unittest` 전체, `node --check desk/static/news.js`, 실제 브라우저에서 국면·공개/기록 기준·날짜 전환과 좁은 화면 확인. 신호·주문·체결 기록을 바꾸지 않아 §6 성과 재생은 대상이 아니며 §6 단위 테스트는 전체 실행에 포함된다 |

### 13.1 운영 — ‘뉴스 근거 업데이트’ 요청

| 순서 | 작업 |
|---|---|
| 1 | `py -m desk news show`로 마지막 판단과 다음 확인 질문을 읽는다 |
| 2 | 현재 국면의 후속 기사와 반대 근거를 검색한다. 최초 보고서/기업 공시 → 보도 원문 → 통신사 재게재 → 재게재 차트 순으로 확인 수준을 남긴다. 유료 보고서를 직접 읽지 못했다면 원문 기사 확인과 구분한다 |
| 3 | 새 사실이 기존 근거와 다른지, 같은 자료의 재보도인지, 측정 대상·기간·단위가 같은지 확인한다. 핵심 변화가 없는 기사를 수량 확보 목적으로 추가하지 않는다 |
| 4 | 아래 필드로 JSON을 만들고 `py -m desk news import <JSON 경로>`로 추가한다. 기록 시각은 명령이 자동 생성하며 과거 날짜로 되돌릴 수 없다 |
| 5 | 새 `assessments`에 지지·반대 근거와 다음 확인 조건을 기록한다. `py -m desk news refresh-prices` 후 `validate`·`show`로 누락과 날짜를 확인한다. 신규 기사가 없으면 신규 없음과 마지막 확인 시각을 답한다 |
| 6 | 원장 변경만 명시적 경로로 `data: <날짜> 뉴스 근거 갱신` 커밋한다. 자동 예약 수집은 현재 설정하지 않는다 |

가져오기 JSON의 최상위 키는 `episodes`, `events`, `assessments`이며 필요한 목록만 포함한다. 실제 예시는 원장을 따른다.

| 목록 | 필수 필드 |
|---|---|
| episodes | `id`, `label`, `benchmark`(미국 종목 코드) |
| events | `id`, `episode`, `source_group`, `title`, `source`, `url`(HTTPS), `published_date`, `available_at`(exact일 때 시간대 포함), `time_precision`(`exact/unknown`), `time_note`, `quality`(`article/syndicated/chart`), `kind`, `stance`, `scope`, `measurement`, `window`, `summary`, `interpretation`, `next_check`; 정정일 때 `supersedes` |
| assessments | `id`, `episode`, `conclusion`, `supports`(기사 id 목록), `contradicts`(기사 id 목록), `next_checks`(질문 목록) |

```bash
py -m desk news show
py -m desk news show --as-of 2026-07-21T23:59:59+09:00 --basis public
py -m desk news show --as-of 2026-07-21T23:59:59+09:00 --basis recorded
py -m desk news import <JSON 경로>
py -m desk news refresh-prices
py -m desk news validate
```
