# GBRC 운영 변경 이력

이 문서는 변경의 시행일과 이유를 보존한다. 현재 실행 규칙은 `AGENTS.md`와 해당 도메인 정본 문서를 따른다. 과거 항목이 활성 정본보다 우선하지 않는다.

## 2026-10-07 — 데스크 화면 명칭 정리

- 배경: 사용자가 화면 이름과 용어도 더 직관적으로 다듬어 달라고 요청했다.
- 탭은 `내 계좌·주문`, `AI 산업 지도`, `거인의 어깨`로 표시한다. 전체 이름 `야간 데스크`를 유지하고 거인의 어깨에는 `AI 섹터·주도주 분석` 설명을 붙였다.
- 분류 전환은 `사업 분야 / 대표 사업 분류 / 산업 대분류`, 종목 비교 범위는 `선택한 분야 / 표시된 모든 분야 / 전체 AI 종목`으로 통일했다. S종목 바로보기는 `전체 S등급 종목 보기`다.
- `시장 폭`은 `전고점 근접 비율`, `큰손의 매매 흐름`은 `펀드 매매·투자자 수급`으로 표시한다. `저점 이후 1위`는 비교 기간을 바꿔도 기준이 같다는 설명을 붙였다.
- 실제 계좌와 계산한 성과를 구분하도록 `7종목 전략 모의 성과`를 사용한다. `회복 등급`의 의미와 계산·매매 조건은 유지했다. AI 지도 갱신 요청은 새 이름과 기존 `AI 탐방 갱신`을 모두 받는다.
- 정본: `docs/desk_system.md` §2.2·§8·§9.
- 검증: 전체 단위 테스트 203개, JavaScript 문법, 임시 계좌·저장 시세를 사용하는 브라우저에서 세 탭의 밝은/어두운 테마·360~2560px 화면·검색·S등급 비교·표 전환·탭 이동을 확인했다. 브라우저 오류와 계좌 기록 쓰기는 없었다.

## 2026-10-07 — 브리핑 엔진을 `gbrc/etf/` 패키지로 이전

- 배경: 바로 앞의 공동 작업 정비 뒤에 사용자가 브리핑 엔진도 옮겨야 하면 옮기고, 필요 없는 복제본은 지우라고 했다.
- 이전 구조의 문제:
  - 루트 `etf_crawler.py`(1,602줄)는 문서에 "호환용"으로 적혀 있었지만 실제로는 수집·보고서 엔진이었다.
  - `set_active_etf`가 모듈 전역 변수 7개를 바꿔 펀드를 전환했고, 보고서는 `print` 출력을 가로채서 만들었다.
  - `gbrc` 패키지가 루트 스크립트를 import하고, 그 스크립트가 다시 `gbrc`를 import하는 순환 구조였다.
  - 누적 브리핑(`cumulative_briefing.py`)은 펀드 코드·가격 티커·원천 주소를 하드코딩했고 테스트가 없었다.
  - 펀드 스냅샷 로더는 세 벌이었다.
- 변경:
  - 엔진을 모듈로 나눴다: `providers`(수집, 네트워크와 파싱 분리), `prices`, `report`, `digest`, `performance`, `cumulative`. 스냅샷 조회는 `storage` 한 곳으로 모았다.
  - 모든 함수가 펀드를 인자로 받고 문자열을 돌려준다. 워크플로와 데스크 `digest`는 `engine.BriefingEngine`을 쓴다.
  - 명령을 `py gbrc.py etf report`, `etf backfill`, `etf cumulative`로 바꿨다. 옛 두 파일과 미사용 함수 12개를 지웠다.
  - `etf backfill`은 날짜 없는 `briefing`의 자동 채우기와 같은 규칙(운용사 기준일 = 요청일일 때만 저장)을 쓴다.
  - 옵션 스캐너 ⑩ ETF 디버전스도 새 조회를 쓴다. 옛 import가 `try`로 감싸져 있어서 그냥 지우면 오류 없이 꺼질 뻔했다.
- 검증:
  - 옛 엔진의 출력과 yfinance 가격 입력 28건을 실데이터로 녹화했다. 같은 가격을 새 엔진에 넣어 다음이 문자 단위로 같음을 확인했다:
    - 7개 날짜(연초·KLAC·CRWD 분할·추석 전후·최신)의 펀드 보고서 14개, 합의 요약 7개, 가격 성과 7개
    - `--no-fetch` 워크플로 보고서 2개
    - 누적 브리핑 2구간(보고서와 요약 JSON)
  - 운용사 원천 캡처 299건을 옛·새 파서에 넣어 원천과 정규화 결과가 같음을 확인했다.
  - 옵션 ETF 신호는 3개 날짜에서 같았다.
  - 테스트는 203개다(수집기 파서 6개, 누적 브리핑 3개 추가).
  - 실제 네트워크로 `etf report`, `etf cumulative`, `py -m desk digest`, 휴장일 `etf backfill`(저장 안 함)을 실행했다.
- 함께 드러난 것: 누적 요약 JSON의 `sectors` 키 순서는 집합 순회 순서라 실행마다 달라진다. 내용과 보고서 본문은 같다.

  - 로컬에만 있던 것은 그 저장소 규칙상 커밋하지 않는 중간 실험 산출물이다.

  - `requirements.txt`: `pyproject.toml`과 중복
  - 테스트·린트 도구(pytest·ruff)는 `pyproject.toml`의 `dev` 선택 의존성으로 적었다.

## 2026-10-07 — 데스크 세 탭의 화면 폭과 탐색 UI 정리

## 2026-09-28 — 야간 데스크가 Ctrl+C로 꺼지던 문제

- 증상: `자료 갱신`·`시세`를 누르면 "Failed to fetch"가 떴다. 서버 창에는 "일괄 작업을 끝내시겠습니까 (Y/N)?"가 남아 있었다. 창 안에서 Ctrl+C가 눌려 서버가 꺼진 것으로, 데이터나 코드 오류가 아니었다. 콘솔에서 선택 없이 누른 Ctrl+C는 복사가 아니라 종료다.

- 서버에 닿지 못하면 화면 맨 위에 "데스크 서버가 꺼져 있습니다" 안내를 띄우고, 5초마다 확인해 켜지면 다시 연결한다. 정본 `docs/desk_system.md` §2.

## 2026-09-27 — 가격 기준일 교정, 수량 기준 실매매, 실매매 합의·관찰군, 심화 분석 명령

- **가격 기준일 버그 수정**: PDF D는 직전 KRX 세션(D-1) 마감 바스켓이다. 국내 종목은 그 세션 종가(오차 0.00%), 해외 종목(미국·일본·홍콩·중국·선물)은 그 세션보다 앞선 마지막 현지 종가(오차 0.25~0.30%)다. 기존 코드는 미국 종목을 D 직전 평일 종가(중앙 오차 2.3%), 일본·홍콩 종목을 D 당일 종가(5.5~6.1%)로 잡았고, 국내 6자리 코드·중국 종목은 가격을 찾지 못해 `N/A`였다. 일일·누적 보고서의 `dW(ret)` 괄호 수익률이 모두 영향을 받았고, 누적 보고서는 보유종목도 같은 달력 날짜 종가끼리 비교하고 있었다.
