# 실적 분석·검증 프레임워크 (Earnings Analysis Framework)

> 활성 범위: **Path-E(실적 분석), Path-V(실적 복기·검증), Path-S(실적 성적표), Path-I(실적 프롬프트 개선)**
> 각 Path는 이 문서를 먼저 읽고 해당 절차만 수행한다. 실적 분석의 원천은 사용자가 제공한 실적 자료이며, 필수 정량값의 누락을 가정으로 채우지 않는다.

---

## 분석의 8대 황금률 (Eight Golden Rules) — 대전제

1. **누락 데이터 식별 및 질의**: 전년 동기 매출, 직전 분기 SBC, 주식수, YTD 매출, 시가총액 등이 없으면 **아래 [데이터 소스 순서](#데이터-소스-순서)대로 보완** 후 분석.
2. **숫자가 스토리를 지배한다**: 경영진 발언·파트너십·파이프라인은 정량 데이터로 증명되어야 하며, 충돌 시 **정량 우선**.
3. **성장률의 2차 도함수 필수 계산**: 성장률(1차)뿐 아니라 성장률의 **변화율(2차)** 계산 → 가속/유지/감속 판정.
4. **숨겨진 가이던스 역산**: 연간 가이던스만 있고 N+1 분기 가이던스 없으면 **[연간] - [YTD 누적]** 으로 잔여 기간 성장률 역산 → 하반기 둔화 여부 판정.
5. **주주가치 희석 정량 측정**: '희석 우려' 모호한 표현 금지. **[SBC / 매출 비율]** + **[희석 주식수 YoY 증가율]** 반드시 계산.
6. **SBC 건전성 다각 평가**: 매출 대비 비율만 보지 말고 **[GAAP 영업이익 - SBC]** 필수 계산. 매출총이익/영업이익/OCF/순이익과 비교.
7. **영업 레버리지 변곡점 포착**: **[매출 YoY 성장률]** vs **[R&D/S&M/G&A YoY 증가율]** 비교 → '이익 확장' 진입 여부 판정.
8. **일회성 항목 선분리 원칙**: 세금혜택/벌금, 미실현 자산 평가손익, M&A 손익 포함 시 → **adj. EPS·순이익을 먼저 별도 계산 후 ①에 적용**. GAAP 수치로 실적 강도를 채점하는 것을 금지. (사례: META $8B 세금혜택 → GAAP EPS $10.44 vs adj. EPS $7.31 / GOOGL $36.9B 미실현 평가익 → GAAP EPS $5.11 vs adj. EPS $2.62)

## 6단계 분석 출력 순서 (반드시 1→6 순서 준수)

### 1) 정량적 가치 계산 (Quantitative Value Calculation)
- 가이던스 상향·장기 계약·자사주 매입 등 모델 반영 가능한 숫자 추출.
- 현재 시가총액 대비 늘어날 수 있는 가치를 금액·% 로 제시.
- **1-1)** 펀더멘털 의미 설명 (이익률 개선 / 현금흐름 증가 / 미래 매출 가시성).

### 2) 핵심 성장궤도 정량 분석 (Key Growth Trajectory)
- **2-A) 2차 도함수**: `성장 가속도 = [N+1 가이던스 YoY] - [N 실제 YoY]` → 재가속/유지/감속
- **2-B) 숨겨진 가이던스 역산**: 잔여 기간 YoY vs YTD 성장률 비교 → 하반기 둔화 리스크
- **2-C) Rule of 40**: `YoY 매출성장률(%) + FCF 마진율(%) > 40%` → '수익성 있는 고성장' vs '현금 태우는 외형성장'
  - **CapEx 전환기 보정** (FY CapEx 가이던스 $50B+ 기업): TTM FCF 마진 외 **Forward Rule of 40** 병기 필수
    `Forward Rule of 40 = 매출 YoY(%) + [(OCF 연환산 - FY CapEx 가이던스 중간값) / 연환산 매출 × 100]`
    → 두 값 차이 >10%p 시 "CapEx 전환기 — FCF 일시 압축" 명시

### 3) S&N Score (Surprise & Narrative Shift Score) — 총 33점

| 항목 | 배점 기준 |
|---|---|
| ① 실적의 강도 | 압도적 비트 5 / 확실 4 / 소폭 3 / 인라인 2 / 미스 1 / 가이던스 하향 D-2 / 역성장 F-1 |
| ② 비즈니스 모멘텀 | 폭발적 가속 6 / 뚜렷한 가속 5 / 완만한 가속 4 / 유지 3 / 뚜렷한 둔화 2 |
| ③ 미래 전망과 성장궤도 | 재가속 암시 7 / 유지 암시 6 / 소폭 둔화 5 / 유지 4 / 잔여 둔화 내포 3 / 철회 F-1 |
| ④ SBC 건전성 | A+ 4: [영업익-SBC]>0 & GP대비 SBC<10% / A 3: <15% 또는 게임체인저 예외 / B+ 2: [영업익-SBC]≤0이나 GP대비 SBC<25% / B 1: OCF 양수 예외 / C 0: 손실을 25%+ 확대 |
| ⑤ 재무적 자생력 | FCF마진>20% 6 / 10~20% 5 / 0~10% & 순부채/EBITDA<3 4 / FCF<0 & 자금조달 완료 3 / 0~10% & 순부채/EBITDA≥3 2 / FCF<0 & 조달없음 D-1 |
| ⑥ 내러티브와 리스크 균형 | 강력+리스크↓ 5 / 변혁적 4 / 긍정적 3 / 매력 vs 리스크 2 / 리스크 여전 1 |

**3-2)** YoY 희석 주식수 증가율(%) — 참고용 표기.

**3-3) ⑤ CapEx 전환기 조정 (FY CapEx 가이던스 $50B+ 기업 한정)**

| 단계 | 계산 | 의미 |
|---|---|---|
| Step 1 | 최근 분기 FCF 마진 | 현재 수익력 스냅샷 |
| Step 2 | (OCF 연환산 − FY CapEx 가이던스 중간값) ÷ 연환산 매출 | 가이던스 반영 연간 FCF 마진 |

→ Step 1과 Step 2 중 **낮은 값**으로 ⑤ 채점. 두 값 차이가 >10%p이면 "CapEx 전환기" 명시 후 2027+ FCF 반등 가능성을 ⑥에서 별도 언급.

**3-4) ⑥ CapEx $50B+ 기업 한정 — ROI 가시성 조정**

| CapEx ROI 유형 | 판단 기준 | 서사 처리 |
|---|---|---|
| 계약/백로그 기반 | Cloud 백로그, 구독 계약 등 측정 가능 잔고 존재 | ⑥ 서사 등급 **+1 상향** 가능 |
| 광고·소비자 기반 | 단가·물량 추정 (경기 민감) | 현재 등급 유지 |
| 선제 투자형 | 미래 수요 예측만 존재, 계약 잔고 無 | 리스크 항목에 **"CapEx ROI 가시성 낮음"** 명시 필수 |

→ 동일 CapEx raise라도 ROI 유형이 다르면 ⑥ 점수와 리스크 기술이 달라져야 함. (사례: GOOGL Cloud 백로그 $460B = 계약 기반 ↑ / META Superintelligence = 선제 투자형 ↓)

### 4) 성장률 퀄리티 퀀트 평가 (Growth Rate Quality)

**4-1)** 시가총액 등급 판별 → 매출 성장률을 백분위로 매핑 → '알파 성장' 해석.

**4-2) 퀀트 평가표**

| 시총 등급 | 중앙값 | 상위 30% | 상위 20% | 상위 10% | 상위 5% | 상위 1% |
|---|---|---|---|---|---|---|
| 메가캡 >$300B | 6.0% | ≥11.0% | ≥16.0% | ≥28.0% | ≥45.0% | ≥70.0% |
| 대형주 $50~300B | 6.0% | ≥14.0% | ≥22.0% | ≥40.0% | ≥60.0% | ≥90.0% |
| 중형주 $10~50B | 3.5% | ≥15.0% | ≥28.0% | ≥55.0% | ≥90.0% | ≥150.0% |
| 소형주 $2~10B | 1.4% | ≥14.0% | ≥30.0% | ≥70.0% | ≥120.0% | ≥220.0% |
| 마이크로캡 <$2B | 1.0% | ≥20.0% | ≥45.0% | ≥100.0% | ≥180.0% | ≥300.0% |

(세부 구간 — 상위 50/45/40/35/25/15% 는 분석 시 보간하여 사용)

### 5) 시장 반응 예상 (Market Reaction Prediction)
- '매우 긍정적 / 다소 긍정적 / 중립 / 다소 부정적 / 매우 부정적' 중 선택.
- **초반(소식 직후)** 과 **중장기** 로 나누어 예측.

### 6) '큰손' 투자자 종합 결론 (Big Pocket Investor Conclusion)
- **6-1) 투자의견**: 적극 매수 / 신중한 비중 확대 / 관망 / 비중 축소 / 투기적 매수 중 선택.
- **6-2) 이유**: 성장 스토리 + 실적의 힘 + 해자(안정성) + 리스크 4개 축 종합.

## 운영 방침

- 실적 자료 불완전 시 → 필요 데이터 먼저 명시, 아래 데이터 소스 순서대로 보완 시도.
- 가정(시가총액·주식수 등)은 **명시적으로 표시**.
- 출력은 반드시 **6단계 순서대로** (1 → 2 → 3 → 4 → 5 → 6).
- S&N 총점과 투자의견은 **볼드 처리**.

### 데이터 소스 순서

앞 순위에 값이 없을 때만 다음 순위로 넘어간다. 보완한 값은 로그에 출처와 함께 적는다.

| 데이터 | 1순위 | 2순위 | 3순위 |
|---|---|---|---|
| 실적 발표일·시각 | `earnings_prefill.py` (yfinance `get_earnings_dates`) | TradingView 컬럼 `earnings_release_date`·`earnings_release_next_date` | IR 공지 WebSearch |
| EPS 컨센서스·실제·서프라이즈 | `earnings_prefill.py` | TradingView `earnings_per_share_forecast_fq`·`earnings_per_share_fq` | WebSearch |
| 매출 컨센서스·실제·서프라이즈 | TradingView `revenue_forecast_fq`·`revenue_fq`·`revenue_surprise_percent_fq` | WebSearch | — |
| 가이던스·경영진 발언 | 사용자 제공 실적 자료 | TradingView `get_documents` 실적콜 녹취록·요약 | WebSearch |
| 분기 재무 추이 (6분기 이상) | TradingView `get_financial_history` (16분기) | WebSearch | — |

- yfinance `.calendar`는 쓰지 않는다. 다음 발표일만 주고 장후 발표를 하루 늦게 준다.
- 두 소스 값이 다르면(예: MU EPS 추정 20.69 vs 20.86) 출처별로 병기하고 평균 내지 않는다.

### TradingView MCP 사용 규칙

- 대화 중 조회해 사람이 읽는 용도로만 쓴다. 스크립트 입력 연결 금지는 `AGENTS.md`를 따른다.
- `get_earnings_calendar` 도구는 쓰지 않는다. 회계분기 말일(`earnings_release_next_calendar_date`)을 발표일로 섞어 반환한다. 날짜는 `get_symbol_data`로 원시 컬럼을 조회한다.
- KRX 종목에 `get_forecasts`를 쓰지 않는다. EPS가 USD 환산값인데 KRW로 표기되고 목표가가 빠진다.
- `get_financial_history`의 분기 라벨은 달력 분기다. 회사 회계분기명과 대조한 뒤 쓴다(MU 5월 분기 = "Q2 2026", 회사 표기 FQ3).
- 데이터는 미국 15분·KRX 20분 지연이다. 장중 가격 판단에 쓰지 않는다.

### ② 검증 (Verification)
트리거: "실적 복기" / "실적 검증" / "<티커> 복기"

1. yfinance로 분석 당시 가격 → 현재가 실수익률 계산 (D+1 / D+5 / D+30)
2. 예측 시장 반응 vs 실제: 매우 긍정(+5%↑), 다소 긍정(+1~5%), 중립(±1%), 다소 부정(-1~5%), 매우 부정(-5%↓)
3. 놓친 케이스 → WebSearch로 돌발 호재/악재 확인
4. `verification` 필드 기록:

```json
"verification": {
  "d1_return": 3.2,
  "d5_return": 7.1,
  "d30_return": 12.4,
  "initial_hit": true,
  "mid_long_hit": true,
  "surprise_catalyst": null,
  "lesson": "FCF 마진 과소 평가 → 이후 Rule of 40 가중치 상향 검토"
}
```

### ③ 프롬프트 개선 루프
- 검증 5건 이상 누적 시 → 체계적 오류 패턴 / 가중치 조정 후보 / 누락 팩터 제안
- 제안은 사용자 확정 후에만 이 문서 또는 관련 정본에 반영하고 `docs/operations_changelog.md`에 기록한다. `CLAUDE.md`에 독립 규칙을 복제하지 않는다. **단정적 수정 금지.**
- 5건 미만 시 개선 제안 비활성화, 단순 누적만.
